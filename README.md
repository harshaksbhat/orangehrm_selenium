OrangeHRM UI Automation Framework

A Python-based UI automation framework for testing the OrangeHRM application using Selenium WebDriver, Pytest, and Page Object Model (POM).

This is a work-in-progress learning project that I am building as I develop and improve my automation skills as a QA professional.

Rather than building the entire framework upfront, I am adding test cases and framework improvements as I progress through my learning. The structure, implementation, and practices will continue to evolve over time.

🚀 Tech Stack

Python – Programming language

Selenium WebDriver – Web UI automation

Pytest – Test framework and test execution

Page Object Model (POM) – Page object and locator management

JSON – Configuration and test environment data

📂 Folder Structure
config/

Contains configuration data used by the framework.

Currently, the folder contains a JSON configuration file with details such as:

{
    "url": "...",
    "username": "...",
    "password": "..."
}


The configuration approach may be expanded or changed as the framework develops.

Note: Credentials should not be committed to a public repository. For a public GitHub project, sensitive values should eventually be moved to environment variables or another secure configuration mechanism.

pages/

Contains the Page Object classes.

Each page object is responsible for storing the locators and UI interactions associated with a particular application page.

For example:

pages/
├── login_page.py
├── dashboard_page.py
└── ...


The purpose of this layer is to keep page-specific Selenium implementation separate from the actual test scenarios.

tests/

Contains the actual Pytest test cases.

Example:

tests/
├── test_login.py
├── test_dashboard.py
└── ...


The tests focus on defining the scenarios and validations, while the Page Object layer handles the corresponding page interactions.

New tests are added as I progress through my automation learning.

reports/

Contains the HTML reports generated by Pytest after test execution.

The reports provide a visual overview of:

Tests executed

Passed tests

Failed tests

Execution details

screenshots/

Contains screenshots captured during test execution.

Currently, screenshots are taken at the end of the test execution to provide visual evidence of the application state.

This area may be enhanced later to capture screenshots conditionally, such as when a test fails.

utils/

Currently reserved for reusable utility/helper functionality.

The folder is intentionally kept as part of the framework structure even though it is currently empty.

As the framework grows, reusable functionality that doesn't naturally belong in the Page Object or test layers can be added here.

conftest.py

Contains Pytest fixtures and shared test configuration.

This provides a central location for setup and teardown functionality that can be shared across tests.

As the framework evolves, additional fixtures and reusable test setup may be introduced here.

pytest.ini

Contains Pytest configuration for the project.

This allows test execution behavior and Pytest settings to be maintained centrally rather than being repeatedly specified from the command line.

requirements.txt

Contains the Python dependencies required to install and run the framework.

Install them using:

pip install -r requirements.txt

🧩 Page Object Model

The framework follows the Page Object Model (POM) design pattern.

The basic relationship is:

                Test Case
                    │
                    ▼
             Page Object
                    │
                    ▼
            Selenium WebDriver
                    │
                    ▼
              OrangeHRM


The intention is to keep:

Test logic inside the tests layer

Page locators and UI interactions inside the pages layer

Configuration inside the config layer

Shared fixtures/setup inside conftest.py

This separation makes the framework easier to understand and provides a foundation for improving maintainability as the test suite grows.

🧪 Running the Tests
1. Clone the repository
git clone <your-repository-url>
cd <your-repository-name>

2. Create a virtual environment
python -m venv venv


Activate it:

Windows

venv\Scripts\activate


macOS / Linux

source venv/bin/activate

3. Install dependencies
pip install -r requirements.txt

4. Run the tests
pytest


For more detailed output:

pytest -v


To run a specific test file:

pytest tests/test_login.py -v
